# Lab 2 关键提示词与任务规范

本实验把 AI 用于阅读代码、提出实现方案、检查边界条件和设计测试。好的提示词需要说清楚：已有代码是什么、目标行为是什么、哪些文件可以修改、哪些测试不能修改，以及什么输出才算验证通过。以下按实际练习整理可复用的关键提示词；源码分析、运行结果分别见 [实验报告](report.md)和[核验记录](verification.md)。

## 1. 识别实验任务和代码入口

**任务规范**：列出物理内存初始化、First-Fit 分析、Best-Fit、Buddy System 的必做内容，区分 Challenge，并找到相应源码与检查函数。

```text
请阅读 Lab 2 指导书以及 kern/mm/pmm.c、default_pmm.c、best_fit_pmm.c、pmm.h。先不要改代码：画出从 pmm_init 到 init_memmap、alloc_pages/free_pages 的调用关系；列出每道必做练习的输入、输出和验收条件；标出指导书中明确写作 Challenge 的内容。对于代码里已有的测试函数，说明它验证了什么、没有验证什么。
```

这样写的原因：先确定任务边界，避免看到 Best-Fit 测试通过就误以为整个 Lab 2 都完成。

## 2. 物理内存发现与 `page_init`

**任务规范**：设备树给出物理内存基址和大小；内核需要建立每页的 `Page` 描述符，只把固件、内核和描述符占用区之外的完整页交给物理页管理器。

```text
请根据 dtb.c、memlayout.h、链接脚本和 pmm.c，实现 page_init。读取 DTB 的内存基址、大小并检查无效值和地址溢出；计算 npage 与虚实地址偏移；把 Page 数组放在内核 end 后的页边界；先将描述范围标为保留，再把真正空闲且按 4 KiB 对齐的页区间传给 init_memmap。不要写死空闲区起点。说明为什么固件、内核、Page 数组和不足一页的尾部不能分配，并用 QEMU 输出核对范围。
```

**验收**：探测范围和空闲范围符合 DTB 与链接布局，Page Init 检查通过；内存基址、大小变化时不依赖硬编码的空闲起点。

## 3. 阅读 First-Fit 并回答思考题

**任务规范**：不重复实现已有的 First-Fit，而是理解 `default_init`、`default_init_memmap`、`default_alloc_pages`、`default_free_pages` 的关系，回答算法能否改进。

```text
请逐函数解释 default_pmm.c 的 First-Fit：空闲链表如何初始化；释放区间怎样登记；分配 n 页时为什么选择第一个足够大的块；拆分余块时哪些属性要更新；释放后怎样按地址插入并合并相邻块。请用一个小型页块例子演示分配和回收，再讨论查找时间、外部碎片及 next-fit 或分级索引的改进与代价。
```

**验收**：报告能从源码解释每个关键函数，并明确“可改进，但会增加维护成本，且不能完全消除碎片”。

## 4. 实现 Best-Fit

**任务规范**：在 `pmm_manager` 接口下实现连续物理页分配；选择所有可容纳请求的空闲块中最小的一块，正确拆分与合并，并保留课程给定测试。

```text
参考 default_pmm.c 和 pmm.h，在 best_fit_pmm.c 中补齐 init、init_memmap、alloc_pages、free_pages、nr_free_pages 和管理器注册结构。空闲块按物理地址排序；每次分配完整扫描链表，选大小不小于 n 且最接近 n 的块；若有余页，建立新的空闲块首页；释放时与物理地址相邻的前后空闲块合并。每一步正确维护 PageProperty、property 和 nr_free。不要修改 basic_check 与 best_fit_check；切换为默认管理器后编译并运行原有检查。
```

**验收**：默认 QEMU 输出 `best_fit_pmm_manager` 和 `check_alloc_page() succeeded!`；课程注入的 Best-Fit 测试也曾通过。算法可进一步使用按大小索引减少全链扫描，但本实验实现保持地址有序，便于合并。

## 5. 实现 Buddy System

**任务规范**：从现有 `pmm_manager` 接口新增伙伴系统，按 2 的幂管理空闲页块；保留可运行的 Best-Fit 版本。这是 Buddy 任务的**实现提示词**。

```text
请在 kern/mm 下实现独立的 buddy_pmm_manager。为每个阶数维护空闲链表；init_memmap 将任意起点和长度的可用页区间拆为尽可能大的、按块大小对齐的 2 的幂块；alloc_pages(n) 把 n 向上取整到 2 的幂，寻找相应或更大的空闲块并逐级拆分；free_pages(base,n) 计算伙伴页号，只在伙伴确实是同阶空闲块时合并。按实际占用容量维护空闲页总数，并检查释放参数与分配记录一致。通过编译开关选择 Buddy，默认仍保留 Best-Fit。
```

**验收**：Buddy 模式能够独立编译、在 QEMU 启动并完成自检；3 页请求实际使用 4 页，5 页请求实际使用 8 页。

## 6. 为 Buddy 设计测试

**任务规范**：用独立测试覆盖拆分、取整、释放与合并，不能只看一次启动输出。这是 Buddy 任务的**测试提示词**。

```text
请为 buddy_pmm_manager 编写不依赖固定物理地址的 check 函数。至少测试 1、3、5 页申请及对应的实际占用；检查释放前后 nr_free_pages 的变化；覆盖 0 页及超过最大支持阶数的请求。遍历每一阶的空闲链表，检查块大小和起点对齐，并证明不存在两个仍可合并的同阶空闲伙伴。保持课程提供的 Best-Fit 检查函数不变；分别启动默认模式和 Buddy 模式，记录实际输出。
```

**验收**：Buddy 自检到达成功输出，默认 Best-Fit 仍能正常启动。自写检查不能替代更大规模的随机压力测试或课程未提供的 Buddy 官方评分。

## 7. 根据结果完成报告

**任务规范**：报告回答全部必做练习，并把算法说明与实际运行结果对应起来。

```text
请依据 Lab 2 指导书、最终源码和本机输出整理 Markdown 报告。先说明本章从 DTB 发现内存到 Page 数组、空闲区注册，再到分配与释放的逻辑线；逐项解释 page_init、First-Fit、Best-Fit 和 Buddy 的核心函数；回答两道算法改进问题；附上两种模式的构建与 QEMU 关键输出，区分课程注入测试与自写测试。记录启动入口修正和 Buddy 测试补强的原因，最后说明这些机制与页表、虚拟内存的关系，以及本实验尚未覆盖的 OS 功能。
```

**验收**：报告中的每个结果都能对应到代码或实际测试；选做 Challenge 不写成必做成果。

## 提示词设计总结

上述提示词从“解释现有接口”推进到“规定正确行为”，再要求“独立验证”。其中实现提示词指定文件、接口与不变量；测试提示词专门寻找分配、释放和合并的反例。把两者分开，比笼统要求“写一个伙伴系统并保证正确”更容易发现错误。
