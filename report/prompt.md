# Lab 2 关键提示词与任务规范

本文件只保留影响任务理解、实现、测试和报告的关键提示词。以下均为提炼稿：P1、P7、P10 根据实际会话中的任务要求整理；P2～P6 沿用原实验稿（提交 `3c60957`）中的整理版本并核对最终代码；P8、P9 根据实际执行的源码调试任务、失败日志和修正过程归纳，不作为当时逐字输入。对应结果见[实验报告](report.md)，具体经过见 [AI 过程记录](ai-process.md)。

## P1. 先核对要求与源码

**spec**：以当前指导书和真实源码为准，区分必做、思考题和 Challenge，明确交付与测试方法。

**来源**：实验开场与交接要求的提炼。

```text
请阅读 Lab 2 当前指导书、已有交接和本地源码，先核对本地与远端分支，保留 Lab 1 和已有修改。讲清本次要做什么、补哪些函数、如何测试和交什么；找到 DTB、page_init、pmm_manager、已有检查函数及 QEMU 源码调试任务。先给分阶段方案和修改范围，经确认再实施；正式报告另行确认。
```

**验收**：任务清单包括 Buddy 和页表/TLB 源码调试，不能只按现有评分器决定实验范围。

## P2. 实现物理内存初始化

**spec**：从 DTB 取得 RAM 范围，为每个受管物理页建立描述符，只登记扣除占用区后的完整空闲页。

**来源**：原实验稿的 `page_init` 提示词整理版。

```text
根据 dtb.c、memlayout.h、链接脚本及 pmm.c 实现 page_init。校验内存基址、非零容量与地址加法溢出，按当前可管理上限截断末端；正确设置虚实地址偏移、npage 和 Page 数组。先将描述范围标为保留，再排除固件、内核、描述符数组和不完整页尾，向 init_memmap 传入非空的完整页区间。不要写死空闲起点，说明 npage 与描述符数量的区别，并用 QEMU 输出核对。
```

**验收**：课程 Page Init 检查通过；不同 RAM 配置以及非法范围、页尾截断、零完整空闲页分别有明确预期。

## P3. 理解 First-Fit 并回答改进问题

**spec**：解释已有算法的四个核心函数，不重复实现。

**来源**：原实验稿的 First-Fit 提示词整理版。

```text
逐函数解释 default_init、default_init_memmap、default_alloc_pages 和 default_free_pages。说明地址有序链表、块首页属性、计数如何维护；用空闲块 8、4、10 页申请 3 页的例子演示选择和拆分，再说明回收时如何合并。讨论 next-fit 或大小索引能改善什么、增加什么代价。
```

**验收**：从源码讲清查找、拆分、合并和外部碎片，并回答算法是否还有改进空间。

## P4. 实现 Best-Fit

**spec**：保持 `pmm_manager` 接口和地址有序链表，选择最小足够块，保留课程测试。

**来源**：原实验稿的 Best-Fit 提示词整理版。

```text
参考 default_pmm.c 和 pmm.h，补齐 best_fit_pmm.c 的六个回调及管理器注册结构。分配时扫描全部空闲块，选大小不小于 n 的最小块；正确拆分余块。释放时按地址插回并合并相邻前后块，维护 PageProperty、property 和 nr_free。不要修改 basic_check、best_fit_check；设为默认管理器，编译运行原有检查，并讨论查找代价和改进方向。
```

**验收**：默认启动完成自检；课程注入检查通过；独立模型核对最小足够块的选择。

## P5. 实现 Buddy System

**spec**：新增独立伙伴管理器，按 2 的幂管理容量，保留默认 Best-Fit。这一条用于实现。

**来源**：原实验稿的 Buddy 实现提示词整理版。

```text
实现独立的 buddy_pmm_manager，为各阶维护空闲链表。init_memmap 将任意合法起点和长度拆为按块大小对齐的 2 的幂块；alloc_pages(n) 向上取整，查找可用块并逐级拆分；free_pages(base,n) 用页索引异或找伙伴，只与范围内的同阶空闲块合并。按实际容量维护空闲页数，在分配首页保留容量供释放校验。提供编译开关，默认仍选 Best-Fit，并说明容量记录能验证什么。
```

**验收**：Buddy 独立编译、启动；3 页占 4 页、5 页占 8 页。容量校验不等于保存了原始请求长度。

## P6. 单独设计 Buddy 测试

**spec**：用计数、对齐、所有权和合并性质寻找反例。这一条用于测试。

**来源**：原实验稿的 Buddy 测试提示词整理版；后半段归纳本轮新增测试要求。

```text
编写不依赖固定物理地址的 Buddy check：覆盖 1、3、5 页、零页、超过支持阶数的请求；核对取整容量与空闲页数；遍历各阶检查大小、对齐及不存在可合并的同阶伙伴。保留课程 Best-Fit 检查。进一步让真实分配器源码运行在主机测试中，用独立占用数组检查返回页不重叠、不越界及计数守恒；从非大块对齐的范围运行固定种子分配/释放序列，再逐页耗尽和逆序回收。用 ASan/UBSan 检查执行，区分主机测试与 RISC-V 内核运行。
```

**验收**：Buddy 自检与主机测试通过，默认 Best-Fit 仍通过；解释为何计数正确仍可能漏掉合并错误。

## P7. 审校已有分支并补足回归

**spec**：保留已有成果，依据可复现失败修正启动、构建和评分，不改评分标准换取通过。

**来源**：实际会话中“拉下来检查审校提升优化”“继续”“接着完善”的要求提炼；具体检查项来自本轮执行。

```text
取得已有 Lab 2 分支，对照最新指导书和官方起始源码审校。复用环境，先运行构建、内核自检和课程评分；若只看到 OpenSBI，用入口、寄存器、异常和页表定位。检查模式切换是否自动重编译、脚本在 WSL 中的换行格式、评分失败是否正确传回及是否清理自身进程。保留课程检查函数，在隔离副本做注入和 DTB 边界测试；记录失败、修正和复测证据。
```

**验收**：默认/Buddy/First-Fit 连续切换和 64/128/256 MiB 启动符合预期；评分 20/20，原始内核确有两项 PASS；故意构建失败时返回失败。

## P8. 观察 QEMU 的页表翻译与 TLB

**spec**：双 GDB 调试一次真实客体访存，覆盖首次未命中、翻译、填充和再次命中，并比较 Bare/Sv39。

**来源**：根据指导书分支任务及实际调试方案提炼。

```text
在不替换系统 QEMU 的前提下准备带符号的独立构建。区分宿主 GDB 调试 QEMU 与客体 GDB 调试 RISC-V，找到本版本的 TLB 查询、填充和 get_physical_address 调用路径。选择能确认执行的目标地址，以条件断点过滤无关访问；实际记录 satp、页表根、VPN、PTE、叶子大小、最终 PA 及分支。让同一地址连续加载两次，观察未命中和命中，再在 Bare 下重复，解释为何 QEMU 在 Bare 下仍可能使用软件 TLB。
```

**验收**：日志同时包含源代码分支、翻译变量和客体加载值。实际采用 TCI 使命中路径可在 C 层观察，不据此推断真实硬件性能。

## P9. 根据失败日志修正调试流程

**spec**：核对断点时机、变量更新时机和进程归属，不仅检查最终 PASS 字符串。

**来源**：本轮失败日志与修正过程的事后提炼，见 [AI 过程记录](ai-process.md)。

```text
分析双 GDB 失败日志：QEMU 为何把带引号的镜像路径当作文件名；Bare 加载为何早于宿主断点启用；next 停在多行赋值续行时，输出参数是否已经更新。逐项依据命令参数、PC 和源码位置修正。完成后检查两次加载值、宿主/客体完成标记、完整输出中的异常以及本次 QEMU 是否退出。清理时只处理记录的本次 PID，并匹配调试二进制与端口。
```

**验收**：Bare/Sv39 各形成查询—翻译—填充—再查询的观察记录，完整脚本成功退出且没有遗留本次调试进程。
